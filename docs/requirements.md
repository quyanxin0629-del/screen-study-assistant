# 屏幕学习助手需求文档

版本：v0.1  
日期：2026-10-13  
状态：开发讨论稿  
暂定产品名：屏幕学习助手

## 1. 产品目标

用户学习、阅读论文或做题时，通过全局快捷键框选屏幕上的内容，直接获得 AI 解释，并自动积累为本地文字笔记和知识图鉴。

核心体验：**看不懂 → 框一下 → 获得解释 → 自动记下来 → 以后再次遇见时能认出来。**

产品应尽量减少切换窗口、复制粘贴、编写提示词和手动整理笔记的步骤。

## 2. 已确定的需求与暂定选择

### 2.1 已确定

- 以 Python 桌面应用实现。
- 可通过快捷键呼出类似截图工具的框选界面。
- 适用于术语、论文段落、问题和题目。
- 解释结果自动保存为问题与答案笔记。
- 笔记直接保存在本地文件夹，不上传云端，不依赖数据库。
- 增加知识图鉴，包含概念名称、解释、个人理解和掌握状态。
- 再次遇到相同概念时，提醒用户此前遇见过它。
- 知识卡片不包含原始截图。
- 优先采用本地 OCR 加文本模型，降低对多模态模型的依赖。

### 2.2 本文暂定的第一版选择

- 为保持保存规则一致，问答笔记也不保存原始截图。截图只在内存中用于识别或本次可选的图片分析。
- 本地笔记格式采用 Markdown，元数据使用 YAML front matter；不使用 SQLite 或云数据库。
- 先完成一个操作系统的完整体验。开发排期暂按 macOS 优先，Windows 后续适配；这属于本文假设，并非用户已确认的平台要求。
- 首次使用和设置页面都提供模型配置入口，让用户填写 API Key、API URL 和模型名称。
- 默认自动保存；掌握状态由用户手动更新。
- 第一版以印刷文字为主，复杂公式与图形题不承诺支持。

## 3. 目标用户与使用场景

| 用户 | 场景 | 希望获得的结果 |
|---|---|---|
| 学生 | 阅读教材，遇到不懂的名词或题目 | 快速理解，并留下可复习的问答 |
| 论文读者 | 阅读英文论文中的术语或难懂段落 | 中文解释、例子和后续追问 |
| 自学者 | 在网页、PDF 或其他软件里学习 | 不改变原来的阅读工具即可获得帮助 |

典型例子：用户在 PDF 中框选“contrastive learning”，工具识别文字并解释；问答自动落盘，图鉴生成“对比学习”卡片。几天后再次框选该词，工具提示以前的掌握状态，并允许打开旧卡片。

## 4. 第一版范围

### 4.1 必须包含

1. 后台常驻、托盘入口及可配置全局快捷键。
2. 屏幕区域框选、取消和重新框选。
3. 本地 OCR、识别文本查看与纠正。
4. 自动解释、回答浮窗、同一问题的连续追问。
5. 本地 Markdown 问答自动保存。
6. 文字知识卡片、个人理解与三种掌握状态。
7. 基于名称和别名的重复概念识别及提醒。
8. 本地笔记浏览、搜索、编辑和删除。
9. 保存目录与 AI 接口配置。

### 4.2 可选扩展

- 专门的公式识别，把公式转成 LaTeX 后交给文本模型。
- 低价多模态接口，作为用户主动选择的“图片分析”入口。
- 从已连接的浏览器或 PDF 获取准确来源。
- 按语义寻找相关概念，而不只是匹配同一名称。
- 知识地图、复习提醒、角色解释、“懂了没”小挑战。

### 4.3 第一版不包含

云同步、账号体系、会员收费、协作分享、整篇论文知识库、自动全屏监控、自动判断用户已经理解、复杂游戏系统。

## 5. 核心操作流程

1. 用户启动应用，设置本地保存目录、AI 接口和快捷键。
2. 用户在其他软件中按快捷键，应用捕获当前屏幕并显示框选遮罩。
3. 用户拖动选择区域；按 Esc 取消时，不发送请求，也不生成笔记。
4. 应用裁剪选区，在本地进行 OCR。
5. 识别完成后自动提交文本解释；浮窗提供“查看识别文字 / 修改后重试”。
6. OCR 未识别出文字时，不提交空请求，提示重新框选或手动输入。
7. AI 回答显示在浮窗中，完整回答成功后自动保存本地问答。
8. 若适合形成概念卡片，生成新卡片或关联已有卡片。
9. 用户可以追问、查看旧卡片、填写个人理解，或按 Esc 返回阅读。

图片分析为可选路径：用户主动选择后，发送框选图片到配置的图片模型；原图仍不落盘。

## 6. 功能需求

### F01：常驻与快捷键

- 应用关闭主窗口后可继续驻留托盘。
- 托盘提供：开始框选、打开笔记、设置、暂停快捷键、退出。
- 快捷键可修改；冲突或注册失败时给出明确提示。
- 同一时刻只允许一个框选流程，避免连续按键弹出多个遮罩。
- 第一次使用时说明实际需要的系统权限，并能在授权后重试。

### F02：区域框选

- 显示截图背景、半透明遮罩和清晰的矩形边界。
- 鼠标松开后开始处理选区；Esc 随时取消。
- 空选区或过小选区不触发 AI 请求。
- 捕获发生在遮罩显示之前，避免把应用自身界面截进去。
- 第一版在鼠标所在显示器内框选；跨显示器框选暂不支持。
- 正确处理屏幕缩放、Retina 像素比例和显示器坐标。

### F03：本地文字识别

- 默认支持中英文印刷文字，保留必要的换行和段落关系。
- OCR 在本地执行，截图不上传到 OCR 服务。
- 用户可查看并修改识别结果，再重新请求解释。
- 不把 OCR 结果视为一定正确，尤其是数字、符号和上下标。
- 碰到复杂公式或图表时，说明文字识别可能不足，提供重新选择、手动补充或可选图片分析入口。

### F04：AI 解释与追问

- 默认以中文回答，保留必要的英文术语。
- 根据内容选择回答方式：术语给出定义和例子；段落解释主要含义；文字题目给出思路及答案。
- 用户不输入问题时，自动生成合适的问题标题。
- 用户可补充具体问题，例如“这一步为什么成立”。
- 回答先提供简短解释，再提供必要细节，避免默认生成过长内容。
- 根据识别文本回答；没有整篇论文上下文时，不声称知道作者在全文中的意图。
- 同一浮窗可以连续追问，上下文属于当前问答。
- 请求在后台执行，界面保持响应；支持取消、失败提示和手动重试。
- 接口支持时逐步显示回答，否则显示加载状态后一次性展示。

### F05：本地问答笔记

- 每次成功完成的初始回答生成一份 Markdown 问答笔记。
- 保存内容：标题、识别文本、问题、回答、追问、关键词、时间、可选来源和关联卡片 ID。
- 自动保存不要求用户额外点击确认。
- 成功后显示“已保存到本地”；失败时保留当前结果并提供再次保存，不显示虚假的成功提示。
- 追问追加到同一份笔记，不为每句话创建新文件。
- 重试不重复生成笔记；用户可以选择用纠正后的版本更新原笔记。
- 不保存原始截图，也不在 Markdown 中嵌入图片或 Base64 数据。
- 用户可打开所在文件夹，并使用其他编辑器读取笔记。

### F06：知识图鉴

知识图鉴与问答笔记分开：问答记录一次学习过程，卡片围绕一个概念长期积累。

| 卡片字段 | 要求 |
|---|---|
| 唯一 ID | 创建后保持稳定，不依赖文件名 |
| 概念名称 | 清晰、可编辑 |
| 别名 | 可记录英文名、中文名及已确认的缩写 |
| 一句话解释 | 用于列表快速浏览 |
| 详细解释 | 概念含义、例子、必要的注意点 |
| 我的理解 | 用户填写，默认留空，AI 不代替用户填写 |
| 掌握状态 | 初次遇见 / 似懂非懂 / 能讲给别人听 |
| 标签 | 支持用户修改 |
| 遇见记录 | 首次时间、再次遇见时间、可选来源、关联问答 ID |

- 新卡片默认状态为“初次遇见”。
- 不根据一次问答或出现次数自动升级状态。
- 简单术语默认生成卡片；题目和长段落保留问答即可，不强行生成无意义概念。
- 第一版每次默认提炼一个主要概念；可以关闭本次卡片生成。
- 卡片生成失败不影响问答保存，可稍后重试。
- 卡片不包含原始截图，个人理解不会被后续 AI 回答覆盖。

### F07：再次遇见提醒

- 匹配已保存的名称和别名，忽略英文大小写、首尾空格等无关差异。
- 对缩写和同名异义词采用保守匹配；无法确定时让用户选择“关联已有卡片”或“新建概念”。
- 已确认的同一概念更新原卡片的遇见记录，不重复创建卡片。
- 一次新问答计为一次遇见；同一问答的追问和重试不增加次数。
- 匹配后提示，例如：“这是你第 3 次遇见它，上次标记为‘似懂非懂’。”
- 只有存在可靠的来源记录时，才说“你上次在另一篇论文里遇到过它”。否则只显示时间和状态。
- 用户可打开旧卡片，阅读个人理解并继续本次解释。
- 新回答保存在本次问答中，不自动覆盖卡片已有的详细解释；提供主动更新入口。

### F08：笔记与卡片浏览

- 分别提供“问答笔记”和“知识图鉴”两个视图。
- 支持按标题、概念名称、别名、关键词和正文搜索。
- 卡片支持按掌握状态筛选；问答默认按时间倒序。
- 可修改标题、标签、个人理解和掌握状态。
- 删除优先移到本地回收区，提供恢复入口。
- 删除问答不自动删除关联卡片；删除卡片不自动删除历史问答。
- 外部编辑 Markdown 后，在重新打开或手动刷新时读取更新；错误文件提示修复，不静默覆盖。

### F09：设置

- 设置保存目录；明确显示当前路径。
- 修改目录仅影响新笔记，不自动搬迁旧文件；笔记浏览切换到新目录。
- 设置快捷键。
- 设置默认回答语言、解释长度和是否自动生成知识卡片。
- 图片分析入口仅在已配置支持图片的接口时启用。
- API Key 使用系统凭据存储，不写入 Markdown、日志或普通明文配置。

### F10：模型配置页面

用户能够使用自己的模型服务，模型配置是首次设置的必要步骤，也是设置页面中的独立入口。

| 界面字段 / 操作 | 要求 |
|---|---|
| API URL | 填写模型服务的基础地址 Base URL；明确提示填写基础地址而非完整请求路径 |
| API Key | 密码输入框，默认遮挡，支持临时显示 / 隐藏；本地免鉴权接口可留空 |
| 模型名称 | 填写服务商要求的模型 ID，不使用展示昵称替代 |
| 接口格式 | 第一版支持一种明确说明的通用聊天 API 格式；URL 可配置不代表任意 API 格式均可用 |
| 测试连接 | 发送一次最小文本请求，检查地址、鉴权、模型名称及响应格式 |
| 保存配置 | 保存地址、模型名称等设置，将密钥存入系统凭据存储 |
| 替换 / 清除密钥 | 支持更换密钥或删除已保存密钥，清除后不继续使用旧密钥 |

- 首次启动时，未配置模型仍可浏览本地笔记和使用 OCR；首次请求 AI 时提示完成配置。
- URL 和模型名称缺失时，给出字段级提示，不发送请求。
- 已保存的密钥仅显示“已设置”，不自动回填或展示真实密钥；不填写新密钥时保留原有密钥，清除操作需明确区分。
- “测试连接”使用当前表单内容，测试前提示会产生一次小额 API 调用；不携带截图或笔记。
- 测试状态包含：测试中、连接成功、鉴权失败、模型不可用、网络失败和接口格式不兼容。
- 测试成功只表示当前文本接口可用，不代表支持图片输入。
- 保存后后续请求使用新配置；正在进行的请求保持其启动时的配置。
- 修改 API URL 时保留用户手动输入的密钥，支持先填 API Key 再填 URL。未手动填写密钥时，只有当前地址与已保存地址一致，才允许复用该服务的已存密钥；新服务不会自动使用旧服务已保存的密钥。
- 自动拼接 API 路径时避免重复添加路径；不支持的地址或响应格式需明确提示。
- 第一版支持单个默认文本模型配置；图片模型配置留作可选扩展。

页面布局示意：

```text
设置 > 模型配置

API URL     [ 服务基础地址（Base URL）           ]
API Key     [ ••••••••••••••                   ] [显示]
模型名称     [ 模型 ID                          ]
接口格式     第一版支持的聊天 API 格式（附填写说明）

[测试连接]  [保存配置]
状态：连接成功 / 错误原因
```

## 7. 本地文件结构

示例：

```text
学习笔记/
├── 问答/
│   └── 2026-10-13/
│       └── 142530-对比学习是什么-a12f.md
├── 知识图鉴/
│   └── 对比学习-c83b.md
└── 回收区/
```

- 文件名包含短 ID，避免同名覆盖；完整 ID 存入文件元数据。
- 元数据包含 `schema_version`，方便后续格式升级。
- 文件中使用 ID 关联问答和卡片，重命名文件不会改变概念身份。
- Markdown 文件是数据来源；搜索索引第一版在内存中重建，不引入数据库。
- 应用配置独立存于系统应用配置目录。
- 写文件采用同目录临时文件加原子替换，降低中断造成损坏的风险；临时文件也不包含截图。

卡片示例：

```markdown
---
schema_version: 1
id: concept-c83b
name: 对比学习
aliases: [Contrastive Learning]
status: 初次遇见
tags: [机器学习]
created_at: 2026-10-13T14:25:30+08:00
updated_at: 2026-10-13T14:25:30+08:00
encounters:
  - time: 2026-10-13T14:25:30+08:00
    qa_id: qa-a12f
    source: null
---

# 对比学习

## 一句话解释
通过拉近相似样本、推远不同样本来学习表示。

## 详细解释
……

## 我的理解

```

## 8. 数据与来源规则

- 本地保存文字笔记，不上传笔记库，不提供云同步。
- 默认文字模式只向配置的 AI 服务发送识别文字、必要指令及当前问答上下文。
- 只有用户主动使用图片分析时才发送选区图片。
- 不自动上传历史卡片正文；发现重复概念时，默认只在本地展示提醒。
- OCR 完成后释放截图对象；可选图片分析在请求结束或取消后释放。应用不将截图写入缓存、日志或临时文件。
- 敏感请求正文与 API Key 不写入日志。
- 来源是可选文字字段。第一版提供手动填写入口，不从截图猜测论文名称、网页地址或页码。
- 这里的“本地保存”描述存储位置；在线文本模型仍会接收识别后的文字。

## 9. 异常与恢复

| 情况 | 产品行为 |
|---|---|
| 屏幕权限未授权 | 显示授权说明，支持返回后重试 |
| 快捷键冲突 | 提示修改快捷键 |
| OCR 为空 | 提示重新框选或手动输入，不调用 AI |
| OCR 错字 | 允许修改文字后重试 |
| AI 超时或网络失败 | 保留识别文本，允许重试，不生成完整笔记 |
| 回答中途取消 | 显示已收到内容，允许手动保存为未完成草稿，不生成正式卡片 |
| 回答成功但卡片生成失败 | 保存问答，单独提示卡片可重试 |
| 本地目录不可写 | 保留当前结果，提示选择可写目录并重试 |
| 模型返回不符合格式的卡片 | 不写入损坏卡片，问答照常保存 |
| 同名概念含义不同 | 允许创建独立卡片，不强行合并 |

## 10. 非功能要求

- OCR、网络请求和文件扫描不阻塞界面主线程。
- 请求或识别进行中显示阶段状态，用户可取消。
- 处理完成后释放不再需要的屏幕图像，避免常驻程序持续积累内存。
- 普通截图流程结束后能快速回到原来的阅读窗口。
- 笔记必须是可读的 UTF-8 文件，无需应用也能打开。
- 性能验证以约定的测试电脑和真实样本为准。暂定目标：快捷键到框选界面出现不超过 1 秒；AI 响应速度单独记录，不把网络耗时当作固定承诺。

## 11. 验收标准

1. 在浏览器和 PDF 阅读器中，快捷键可以呼出框选；Esc 取消不会调用 AI 或创建文件。
2. 对约定的清晰中英文文字样本，可以识别、查看文字并获得中文解释；错误文字可修改后重试。
3. AI 请求进行中，窗口能移动、关闭或取消，不出现界面冻结。
4. 成功问答自动生成本地 Markdown，包含问题和回答，且没有截图文件、图片引用或 Base64 图像。
5. 连续追问追加到同一笔记；重试不会生成重复文件。
6. 术语问答可生成卡片，个人理解留空，状态默认为“初次遇见”。
7. 用户填写个人理解并修改状态后，重启应用内容仍保留。
8. 再次框选已确认别名的同一概念，提醒已有状态，更新遇见记录，不重复创建卡片。
9. 追问和重试不增加遇见次数；同名异义概念可以保持独立。
10. 能搜索、编辑、删除和恢复笔记，外部修改后刷新可见。
11. 模拟断网、目录不可写和卡片生成失败时，应用保留可恢复内容并准确提示。
12. 在目标平台的缩放屏幕与第二显示器上，选择区域和识别图片一致。
13. 默认模式的网络请求不包含截图或整份笔记库；配置文件和日志不包含明文 API Key。
14. 首次设置与设置页面可填写 API URL、API Key 和模型名称；保存并重启后仍可使用，密钥默认不可见。
15. 测试连接使用当前表单配置，能够区分鉴权、模型、网络和接口格式错误；失败不清空用户已填写的非敏感字段。
16. 更换服务地址时不会自动使用旧服务保存的密钥；清除密钥后，新请求不再使用原密钥。
17. 先填写 API Key 后逐字输入或修改 URL，手动输入的密钥不会丢失，且仍默认隐藏。

## 12. 建议技术方案

| 模块 | 暂定方案 |
|---|---|
| 桌面界面 | Python + PySide6 |
| 屏幕捕获 | mss，具体平台验证后可替换为系统接口 |
| 全局快捷键 | pynput，具体平台验证后可替换为原生热键注册 |
| OCR | 本地普通 OCR 模块，优先评估 PaddleOCR PP-OCR 系列 |
| AI 调用 | httpx，封装可替换的文本 / 图片模型接口 |
| 本地存储 | Markdown + YAML 元数据 + Python 文件操作 |
| 异步处理 | Qt 工作线程和信号 |
| 桌面打包 | PyInstaller，按目标平台单独构建和验证 |

模型供应商、具体模型和快捷键组合属于可配置项，不绑定在核心业务逻辑中。复杂公式显示与公式识别作为后续扩展，不阻塞第一版。

## 13. 开发顺序

### 阶段一：验证系统交互

实现托盘、快捷键、单显示器框选、本地 OCR。优先验证权限和缩放坐标，确认真实屏幕内容可正确识别。

### 阶段二：完成问答与本地保存

实现 AI 接口、回答浮窗、追问、取消及失败重试，自动保存 Markdown，并提供问答浏览与搜索。

### 阶段三：完成知识图鉴

实现卡片生成、掌握状态、个人理解、别名匹配、重复概念提醒以及卡片搜索。

### 阶段四：形成可分发版本

完成目标平台打包、首次设置、多显示器验证、异常恢复和完整验收。

第一版完成的定义：用户可以在实际阅读中反复完成“框选、理解、回到阅读”，并在重启后找到自动保存的问答与卡片。


## 2026-10-14 交互与识别补充

- Windows 优先 GPU，本地无兼容 GPU 或 GPU 初始化 / 执行失败时使用 CPU，不能因此阻断解答；允许手动选择 CPU。
- 使用 DirectML 覆盖兼容的 NVIDIA / AMD / Intel GPU，显示实际启用的运行后端和耗时；不承诺 GPU 一定比 CPU 快。
- 回答悬浮窗采用 iOS 风格圆角与玻璃背景；支持系统原生效果时优先使用，较旧系统提供半透明样式。
- 位置依据整个截图选区计算，优先邻近且不遮挡选区；多屏与缩放场景限制在对应显示器可见范围内。
- 关闭悬浮窗后仍提供直接打开主页面和本地笔记的入口：可拖动快捷工具条、系统托盘 / 菜单栏；回答窗也可打开笔记。


## 2026-10-14 笔记补充（覆盖此前每次问答单独建文件的设计）

- 新问答统一追加到保存目录下的一个 `学习笔记.md`，追问也追加到该文件。
- 不再使用“问题 1 / 回答 1”这样的章节标题。直接加粗问题正文，接着展示回答；用小字时间和分隔线区分记录。
- 持久化在后台异步队列进行，不阻塞回答显示和后续追问；关闭悬浮窗仍完成已完成答案的写入。
- 文件写入失败不能中断回答或禁止追问；按顺序追加，避免并行写入交错和重试重复。
- 笔记入口直接打开这个 Markdown 文件，不必先打开设置页。

## 2026-10-14 截图会话合并（覆盖逐轮追加的设计）

- 一次框选是一条学习笔记，初始问题及所有成功完成的追问合并到该条记录。
- 问题整理成一段完整提问，可包含多个问题，保留必要条件、数值、公式和已确认方向。
- 回答按知识点去重整合，覆盖问题的关键结论和例子，不按对话轮次编号；不同截图之间保留分隔线。
- 先异步保存全部已完成内容，再通过后台文本模型整理，仅发送当前截图的问答，不读取整份笔记库。整理期间不阻塞回答或追问。
- 整理失败或退出取消时保留完整记录；旧版本的整理不得覆盖新增追问。关闭浮窗仍可完成整理。
- 原文重试成功后更新当前截图的同一条记录。外部编辑的内容不强行覆盖；历史条目不猜测合并。

## 2026-10-15 聊天界面补充

- 浮窗以独立聊天气泡展示对话：用户问题在右侧，AI 回答在左侧，支持多轮上下文。
- 发出有效追问后立即显示原始问题及等待状态，不依赖模型首个内容或最终答案；回答逐步填入对应气泡，不重复插入问题。
- 停止或失败时保留已发送的问题和已生成内容；重新提问不使旧消息消失，修改原文重新解答时清空本次显示的旧对话。
- 保留离线公式渲染、Markdown、选择复制、玻璃背景和异步合并笔记；聊天中的原始追问措辞不被模型的笔记问题替换。
